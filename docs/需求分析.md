# 字符长度生成器 · 需求分析说明书

> 版本：v1.0（关键决策已确认）
> 目标用户：测试工程师（长度类边界测试数据准备）
> 交付形态：单文件 `index.html`，零依赖，可离线运行，可直接部署 GitHub Pages

---

## 1. 项目定位

### 1.1 要解决的问题

测试工程师拿到监管/接口规范表（如征信报文的「长度要求」列）后，需要为每个数据项手工构造"刚好卡在长度上限"的测试数据。
现状痛点：

| 痛点 | 现在的做法 | 代价 |
|---|---|---|
| 长度靠手工数 | 复制粘贴后肉眼数汉字/数字 | 易错、耗时长 |
| 字节数算不清 | 中文 2 字节还是 3 字节靠经验 | 边界值做不准，漏测 |
| 数据不留痕 | 生成完就丢，下次重做 | 无法复用、无法回归 |
| 找不到旧数据 | 翻聊天记录 / 翻临时文本 | 效率低 |
| 导出到 Excel 变形 | 多空格、丢前导零、变科学计数 | 用例表要手工返工 |

### 1.2 一句话目标

**输入长度要求（或直接粘贴规范表），一键生成符合该长度约束的测试数据，自动校验字符数/字节数，全程留痕可搜索，并支持勾选式导出为可直接粘贴进 Excel 测试用例表的干净文本。**

## 2. 核心概念：长度要求写法解析

### 2.1 规范原文 → 结构化字段

| 规范原文（原图） | 归一化类型 | 长度 | 长度模式 | 字符集 | 生成策略 |
|---|---|---|---|---|---|
| `vchar（180）byte` | VARCHAR | 180 | 上限（可变） | 任意 | 中文 / 英文 / 混合 |
| `N11` | N | 11 | 固定 | 0-9 | 定长数字（可套手机号模板） |
| `N..15` | N | 15 | 上限（可变） | 0-9 | 变长数字 |
| `ANC..100` | ANC | 100 | 上限（可变） | A-Za-z0-9 | 字母数字混合 |
| `ANC..80` | ANC | 80 | 上限（可变） | A-Za-z0-9 | 字母数字混合 |
| `AN..30` | AN | 30 | 上限（可变） | A-Za-z | 纯字母 |
| `C..50` | C | 50 | 上限（可变） | 任意 | 任意字符 |
| `uInt..15` | UINT | 15 | 上限（可变） | 0-9 | 无符号整数 |
| `decimal(18,2)` | DECIMAL | 18 | 固定 | 0-9 + 小数点 | 定点金额 |
| `YYYYMMDD` / `Date` | DATE | 8 | 固定 | 0-9 | 合法日期 |
| `--` | NONE | — | — | — | 无长度要求，跳过 |

### 2.2 解析必须处理的脏数据（原图真实存在）

1. **全角括号**：`vchar（180）byte` 里的 `（）` 是中文全角，必须归一化后才能正则匹配。
2. **全角句点**：部分规范写成 `ANC．．100`（两个全角点），要兼容。
3. **间距不定**：`vchar (180) byte`、`ANC . 100`、`ANC。。100` 都要能识别。
4. **大小写不定**：`vchar` / `VARCHAR` / `Vchar`、`uInt` / `UINT` / `uint`。
5. **单元格自带换行**：从 Word 表格复制的单元格末尾常带 `\r\n` 或 `\x07`，需剥离。
6. **`--` 表示无限制**：不生成，或标记为「无需测试」。
7. **同一数据项重复出现**：`数据发生机构名称` 出现 2 次且长度要求相同 → 批量导入时需去重。

### 2.3 ⭐ 关键歧义：`byte` 到底是字节还是字符

这是本需求**唯一的架构级分歧点**，必须先定。

| 口径 | 含义 | `vchar(180)` 生成的汉字数 | 风险 |
|---|---|---|---|
| A 按字符数 | 生成 180 个字符 | 180 个汉字 | 真实入库 540 字节（UTF-8）会被截断 |
| B 按 UTF-8 字节 | 最多 180 字节 | 60 个汉字 | 若系统用 GBK 则偏保守 |
| C 按 GBK 字节 | 最多 180 字节 | 90 个汉字 | 若系统用 UTF-8 则超长 |

**已确认方案（v1.0）**：
- **默认按「字符数」口径**：`vchar(180) byte` → 生成 180 个字符（用户确认）。
- 解析到 `byte` 关键字时，**仍实时同时显示三个数值**：`字符数 / UTF-8 字节 / GBK 字节`，方便对照。
- 保留「字节口径」为**可切换选项**（全局设置内），默认关闭。原因见下方风险提示。

> ⚠️ **风险提示（保留意见）**：规范原文写的是 `byte`，不是字符。若被测系统确实是按字节截断，那么按「180 个字符」生成的汉字（UTF-8 下 540 字节 / GBK 下 360 字节）会被截断，这时用它做「刚好卡上限」的边界测试会**偏松**——因为真正的边界是被截断后的那 60 / 90 个汉字。
> 建议的使用方式是：长度值填**真实边界值**时用字符口径；做**入库截断类测试**时切到字节口径。两者都保留，才不至于漏测。

## 4. ⭐ 专项：「导出 Excel 多一个空格」根因分析与方案

### 4.1 根因矩阵

| 编号 | 根因 | 典型触发点 | Excel 中的表现 | 检测难度 |
|---|---|---|---|---|
| R1 | 拼接分隔符带了空格，如 `row.join(', ')` | 代码里手写逗号+空格 | **每个单元格首部多 1 个空格** | 极高（肉眼像正常） |
| R2 | 值内含不换行空格 `U+00A0`（源自 `&nbsp;`） | 从 DOM 取文本、模板里插了 `&nbsp;` | 看着是空格，`TRIM()` 去不掉 | 高 |
| R3 | 值内含全角空格 `U+3000` | 中文排版习惯带入 | 同上，且宽度更宽 | 高 |
| R4 | 零宽字符 `U+200B/200C/200D/2060` | 复制自网页、微信、PDF | 完全不可见，导致字符串比较失败 | 极高 |
| R5 | UTF-8 BOM `U+FEFF` 处理不当 | 文件头加 BOM 后又被当数据读 | 首个单元格出现 `﻿` 或乱码 | 中 |
| R6 | 行尾多一个分隔符（`+ '\t'`） | 拼接收尾处理不当 | 粘贴后右侧多一个空列 | 中 |
| R7 | 换行只用 `\n` 未用 `\r\n` | 非 Windows 换行约定 | 行粘连 / 多空行 | 中 |
| R8 | 复制走 `text/html` 富文本风味 | `Clipboard API` 写入 `text/html`，HTML 源码带缩进与换行 | HTML 缩进与换行被转成空格 | 中 |
| R9 | 从页面直接 `innerText` 取内容 | DOM 里的换行与缩进被当成文本 | 内容前后多空白 | 中 |

### 4.2 对策设计（写入代码规范）

```text
【导出前必过的一道闸门】sanitizeCell(value)
  1. String(value)
  2. 剔除零宽字符: /[\u200B-\u200D\u2060\uFEFF]/g
  3. 不换行空格 U+00A0 -> 半角空格
  4. 全角空格 U+3000   -> 半角空格
  5. 制表符/换行 -> 单空格（避免串列）
  6. 去掉首尾空白: .trim()
  7. 保留内部单个空格，但把连续多空格压成 1 个（可配置）

【拼接规范】
  - 列分隔符：逗号严格用 ","；TSV 严格用 "\t"。分隔符后禁止任何空格
  - 行分隔符：统一 "\r\n"
  - 行末禁止追加分隔符
  - 结尾不加多余空行
  - 剪贴板复制时不加 BOM；只有下载文件时才在最前面加一次 "\uFEFF"

【CSV 转义】按 RFC 4180
  - 字段含 , " \r \n 时用双引号包裹，内部 " 转成 ""
  - 不做 "美化"（不得为了让源码好看而加空格或换行）
```

### 4.3 三种导出方案对比与推荐

| 方案 | 实现方式 | 空格风险 | 中文乱码风险 | 推荐度 |
|---|---|---|---|---|
| A. CSV 文件下载 | `Blob` + UTF-8 BOM + RFC4180 转义 | 低（受 R1/R2 影响） | 低（有 BOM） | ★★ 备选 |
| B. TSV 剪贴板复制 | `text/plain` 只写 TSV，`\t` 分隔 | 低 | 无（剪贴板无编码问题） | ★★★ 默认 |
| C. HTML 表格剪贴板 | 同时写 `text/html`（紧凑无缩进的 `<table>`） | **极低** | 无 | ★★★ 主推 |

**最终推荐**：
- 主按钮：**「复制到 Excel（推荐）」** → 剪贴板同时写入 `text/html`（紧凑表格）与 `text/plain`（TSV 兜底）。
  这样 Excel / WPS 走 HTML 风味直接按单元格还原，**完全绕开 CSV/TSV 的解析环节，从根本上不会多空格**；不支持 HTML 风味的编辑器自动降级用 TSV。
- 次按钮：**「导出 CSV 文件」** → 加 BOM、`\r\n`、严格转义、分隔符后无空格。
- 辅助按钮：**「复制纯值」** / **「复制为 Markdown 表格」** / **「导出 JSON（备份用）」**。

### 4.4 可验证的验收标准

- AC-1：导出的每一格做 `cell === cell.trim()` 必须成立。
- AC-2：导出内容中 `\u00A0`、`\u3000`、`\uFEFF`、`\u200B-\u200D` 出现次数必须为 0。
- AC-3：粘贴到 Excel 后，第 1 行第 1 列内容严格等于表头首列，无前导字符。
- AC-4：11 位手机号字段粘贴后仍为 11 位文本，不变成 `1.38E+10`。
- AC-5：导出 1000 行后，Excel 中行数 = 1000，列数 = 勾选列数，无额外空列/空行。
- AC-6：内置「导出前自检」能对故意注入的 `&nbsp;` / 全角空格样本给出报警，且「一键清洗」后报警归零。

## 5. 技术方案

| 项 | 选型 | 理由 |
|---|---|---|
| 形态 | 单个 `index.html`（HTML + CSS + JS 内联） | 双击即用、可离线、GitHub Pages 零配置、方便发给同事 |
| 依赖 | 零第三方库 | 离线可用、无供应链风险、体积小 |
| 存储 | `localStorage`（记录）+ `JSON` 导入导出 | 无需后端；注意约 5MB 上限，需配合容量提示 |
| 编码计算 | 字符 `[...str].length`；UTF-8 `TextEncoder`；GBK 用汉字 2 字节规则估算 | 浏览器无原生 GBK 编码器，标注为估算 |
| 剪贴板 | `navigator.clipboard.write`（含 `text/html` + `text/plain`），失败降级 `execCommand` | 兼容 http 环境 |
| 主题 | 浅色为主，CSS 变量预留深色 | 符合你的视觉偏好 |
